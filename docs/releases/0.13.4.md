# gonk-core 0.13.4

All 20 `@gonk/*` packages in gonk-core move to 0.13.4. Only `@gonk/skills`
changed. This release is on the local registry only so far.

gonk-extensions moved every skill read and write onto `@gonk/skills` on
2026-11-20, and that showed four faults:

- **Rewrites dropped fields.** Pin, record usage, activate, patch and promote
  re-rendered the manifest from the fields the registry knows, so
  `created_at` and every unknown key were lost on each skill use. Now each
  rewrite changes only its own keys and keeps every other byte of the
  frontmatter: order, comments, wrapping.
- **One bad field hid the skill.** A field that did not parse (for example
  `provenance.pinned_at: 2026-07`) removed the skill from every read. Now the
  skill is listed, the field is left out of the record and stays in the file,
  and the summary has `warnings: [{ field, message }]`.
- **restore, promote and archive without a scope threw** when a tier had no
  home, such as the persona tier with no active persona. They now skip it.
- **Crash recovery could roll back committed work.** A host recovering
  another host's crashed transaction asked its own journal for the receipt,
  found none, and restored the old files. Pending transactions now record the
  writer's journal id and whether the files were finished. Another host keeps
  finished files and restores unfinished ones. Opening a registry while
  another holds the transaction lock no longer throws.

`SkillLifecycleJournal` gains an optional `journalId(scope)`. Journals
without it behave as before.
