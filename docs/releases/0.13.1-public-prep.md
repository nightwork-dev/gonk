# 0.13.1 public release preparation

This branch prepares the nine public packages for npm: `@gonk/utils`,
`@gonk/auth`, `@gonk/scope`, `@gonk/tool-registry`, `@gonk/tool-orchestrator`,
`@gonk/tool-registry-mcp`, `@gonk/context`, `@gonk/store` and `@gonk/skills`.
It changes comments, READMEs and CHANGELOG wording only. No code behaviour
changed and no version was bumped. The release owner versions and publishes.

## Outcome

- The packed tarballs contain no personal names, home paths, private machine
  names, unpublished projects, internal ticket codes, keys or tokens, apart
  from the items in "Left for the release owner" below.
- All nine READMEs are rewritten for a developer who arrives cold. The main
  examples were run against the packed tarballs.
- `npm publish --dry-run` passes for all nine.

## Scan method

1. Build the nine with `pnpm nx run-many -t build`, then `pnpm pack` each into
   a temporary folder and unpack the tarballs. This is the file set that
   `changeset publish` sends.
2. Scan every unpacked file. A `.map` file is scanned twice: as raw text, and
   as each embedded `sourcesContent` entry, which is reported against its
   source path.
3. Look for these categories: person and agent names, email addresses, home
   paths, private machine and network names, the local registry port,
   unpublished private project names, internal dates and process words,
   internal ticket codes, names of unpublished packages and tools, and key or
   token shapes.
4. Sweep the non-dictionary words of every shipped comment and README by hand
   for anything the patterns missed. This found the unpublished tool names,
   a private ingress project name and the store README's ticket codes, which
   were then added to the patterns.
5. Compare every `@gonk/*` name that appears in shipped files with the
   packages on the public npm registry. All of them are published there.

### Sourcemaps

Every package builds with `sourcemap: true`, and tsup embeds
`sourcesContent`. 62 of the shipped `.map` files carry full source, so every
source comment ships. The scan therefore covers the full source of each
bundle. The `sources` lists hold relative paths only.

### A usability finding

`createHttpMcpServer` answers HTTP 500 with "internal error" and logs nothing
when `makeAuthContext` returns a principal that differs from the one the
server authenticated. The cause is visible only by reading the source. A clear
error message, or a log line, would save a new user time. This branch does not
change it.

## READMEs

Each README now has the same shape: what the package is and how it fits with
the other `@gonk/*` packages, install, the shortest real first use, the main
capabilities in the order a typical user needs them, entry points, and the
license.

Main corrections against the code:

- `makeBaseContext()` needs `{ auth }`. The old tool-registry README called it
  with no arguments and said trusted callers could omit `ctx.auth`. The
  registry refuses every call without an `AuthContext`.
- The orchestrator registers six meta-tools, including `tool_explain`. The old
  README listed five.
- The old MCP README's stdio example read `request.http?.authInfo`, which is
  always empty on stdio, and its last section gave one write-policy default
  for every transport.
- Scope writes fail when a tier has no root folder, and a tier that shares its
  home with a narrower tier is not used. The new example creates its roots
  with `ensureRoot()`.
- The project-root markers are `.git`, `.claude`, `.pi`, `agents`, `.agents`
  and `.gonk`.
- The JSON-route example builds its `AuthContext` from the principal that the
  server authenticated, which the server requires.

Recent features moved down: bundled skills in the skills and MCP READMEs, the
development router and protocol revisions in the MCP README, and long-running
tool dispatch in the tool-registry README. Status lines, phase lists and
internal planning notes were removed.

registry, with `@mirk/store@0.13.0`, `@modelcontextprotocol/client` and

Node 24, and type-checked with `tsc --strict`.

| `tool-registry-mcp` | Packaged skills over stdio | The client listed `skill_list` and `skill_get` and called `skill_list`. |
| `tool-registry-mcp` | JSON routes | `GET /tools` and `POST /tools/greet` worked with a key. A request with no key got 401. |
| `tool-registry-mcp` | Web handler, importer | Type-checked only. |
| `tool-registry-mcp` | `gonk-mcp-http` | The command started and answered an MCP `initialize`. |
| `skills` | Read, create and patch, bundled tools | Ran against a temporary project. |
| `scope`, `store`, `context`, `tool-orchestrator`, `auth`, `utils` | Quick starts | Ran and type-checked. |
