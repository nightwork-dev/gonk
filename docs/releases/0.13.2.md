# gonk-core 0.13.2

All 20 `@gonk/*` packages in gonk-core move to 0.13.2 as one fixed version set.
Nine of them are the candidates for the public npm release: `@gonk/utils`,
`@gonk/auth`, `@gonk/scope`, `@gonk/tool-registry`, `@gonk/tool-orchestrator`,
`@gonk/tool-registry-mcp`, `@gonk/context`, `@gonk/store` and `@gonk/skills`.

## What changed

- **A clear refusal for a principal mismatch.** When `makeAuthContext` returns
  a different principal than the one the request authenticated,
  `createHttpMcpServer` and `createWebMcpHandler` now log the mismatch and
  refuse the request. JSON routes answer 403 with the reason. Before, they
  answered 500 "internal error" and logged nothing. The test is
  `packages/adapters/tool-registry-mcp/test/http-principal-mismatch.test.ts`.
- **READMEs for the nine public packages.** Each README is rewritten for a
  developer who meets the package for the first time. Source comments no
  longer carry internal notes. These changes do not change code behaviour. The
  scan method and the README corrections are in `0.13.2-public-prep.md`.
- **CHANGELOG wording.** The 0.7.0 to 0.13.0 entries of the other six packages
  use the same wording as the nine public packages.

## A decision kept as it is

`RUNTIME_STATE_KINDS` in `@gonk/scope` keeps `"autotune-claims"` and
`"objective-watch"` (Neve, 2026-11-19). They are names of state folders that
hosts already write on disk. A `.agents` or `.gonk` namespace that holds only
these folders does not mark a project root, and removing the names would
change that for existing folders.
